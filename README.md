# OCS LINK 0.1.3 / online-switcher

## GitHubから使用する場合

**[完成版のWindows ZIPをダウンロード](https://github.com/MPCSTAFF07/online-switcher/releases/latest/download/OCS-Link-Windows.zip)**

完成版は展開して `START-HOST.bat` / `START-SENDER.bat` で起動します。SDKやビルド操作は不要です。

`Code → Download ZIP` はソースコードです。こちらにはexeを含めていません。

- 完成版：上記リンク、または **Releases** から入手。ActionsのArtifactsにも同じ内容を保存します。
- 自分のWindowsでビルド：ルートの `BUILD.bat` を実行。SDKがない場合はWinGetで.NET 8 SDKを導入します。`dist/OCS-Link/sender/`・`dist/OCS-Link/host/` を作成し、`dist/OCS-Link/` 内の `START-HOST.bat` / `START-SENDER.bat` で起動します。

以下はビルド済み配布物向けの説明です。

別の家のWindows PCから、最大6枠の画面と音声を配信OBSへ送るシステムです。
送信側はネイティブのWindowsアプリで、ブラウザー・OBS・SRT・Tailscaleは使いません。
映像通信はWebRTC（H.264 / DTLS-SRTP）、音声はOpusです。
配信側にはOBSが必要です。スイッチング画面はブラウザーで開きます。

## 入っているもの

- `START-HOST.bat`：配信PCで接続受付と操作画面を起動
- `START-SENDER.bat`：送信PCで送信アプリを起動
- `SETUP-SENDER.bat`：送信PCにFFmpegを導入（初回のみ）
- `sender/`・`host/`：ビルド済みWindows x64アプリと同梱.NETランタイム。各フォルダー全体を保持
- GitHubの `Core/`・`Sender/`・`Host/`・`Tests/`：フルソース
- `deploy/`：HTTPS公開用Caddy設定例、TURN設定例
- `VALIDATION.md`：検証済みの内容と、実機確認が必要な内容

## まず配信PC 1台の中で試す

1. ZIPを展開。ZIPの中から直接実行しないでください。
2. OBSで「ツール → WebSocketサーバー設定」を開き、有効化。ポート4455、パスワードを確認します。
3. `START-HOST.bat` を実行。`http://localhost:17640` が開きます。
4. 初回に作られる `host/config.json` の `AdminPassword` でログインします。
5. 左の「接続設定」を表示。OBSのパスワードを入力して保存 → 上部「OBS接続」。スタジオモードが有効になります。
6. 「送信PC」の「受信用シーンを6枠追加」を押します。
7. 同じPCで `SETUP-SENDER.bat` を実行してFFmpegをインストール。
8. `START-SENDER.bat` を実行。配信側の「PC 01 → 接続コード」をコピーして貼り付け、送る画面・音声を選択して送信開始。
9. OBSの `OCS / PC 01` に映像が出ることを確認。

`localhost` の接続コードは他の家では使えません。他の家で使用する前に、次の公開設定が必要です。

## 別の家から使うための設定

ドメインだけでは接続経路や中継サーバーは作れません。次のどちらかを用意します。

### A. 配信PCを接続先として公開（VPSなし）

1. 配信側に外部から到達可能なグローバルIPが必要です。CGNATや一部の共有IPv4回線ではこの構成は使えません。
2. ドメインのDNSで、例 `relay.example.com` のAレコードを配信側のグローバルIPv4へ向けます。動的IPなら変更時にDNS更新が必要です。
3. Caddyを配信PCに導入し、`deploy/Caddyfile.example` を自分のドメインに書き換えて起動します。
4. ルーターでTCP 80 / 443を配信PCへ転送し、Windowsファイアウォールでも許可。OCS本体の17640は外部へ公開せず、Caddyから接続します。
5. 「接続設定 → 公開URL」を `https://relay.example.com` に変更して保存。
6. 新しい接続コードを送信者に渡します。既にコピーしたコードは更新されません。
7. WebRTCはSTUNで直接通信を試みます。TCP 443が届いても、映像用ICE接続が成立するとは限りません。映像がつながらない組み合わせでは、次のTURN中継を設定してください。

### B. 公開サーバーで接続受付（配信PCを公開しない）

Hostを公開Windowsサーバーで動かせますが、この初版はOBS操作・ローカル受信URLが同じ配信PCにある構成を標準にしています。サーバー分離にはOBSへの経路と受信ソースURLの調整が必要です。未設定のままVPSへ移しても完成しません。

### TURN中継が必要な場合

利用可能なTURNサーバーのURL・ユーザー名・パスワードを、接続設定のICEサーバーJSONに追加します。

```json
[
  { "urls": "stun:stun.l.google.com:19302" },
  { "urls": "turn:turn.example.com:3478?transport=udp", "username": "ocs-user", "credential": "十分に長いパスワード" }
]
```

`deploy/turnserver.conf.example` はcoturnの設定例です。TURNを自分で立てる場合、3478/UDP・TCPおよび指定したUDPリレーポートの到達性が必要です。NATの内側ならexternal-ipの設定とポート転送も必要。TLS 443のTURNは、この例には含めていません。

TURNを通ると映像の帯域が中継機を通ります。6台×2.5Mbpsなら、中継機は概算で受信15Mbps＋送信15Mbps、配信PCは受信15Mbps（各種オーバーヘッド別）です。VPSを使う場合は転送量も確認してください。

## 送信側の使い方

- エンコーダー自動判定：NVENC → Quick Sync → AMF → CPUの順で短いエンコードを実行して確認します。
- GPUが利用できない場合は、CPU・最大720p30に制限してログへ表示します。
- GPU判定は起動時に毎回実施。異なるメーカーのPCを同じ配布物で扱えます。
- 画質：720p30 / 2.5Mbps、1080p30 / 5Mbps、1080p60 / 8Mbps。
- 音声：既定のPC再生音、既定マイク、個別の入力デバイス、音声なし。初版では同時ミックスは未対応。
- 最小化するとトレイに入り、送信は継続します。トレイをダブルクリックで復帰。
- 接続コードはディスクに保存しません。画質などの設定のみ `%LOCALAPPDATA%/OCS-Link/sender.json` に保存。
- 画面の取得はFFmpeg gdigrab。ウィンドウを最小化すると正常に取得できないことがあります。ゲーム画面が黒い場合はボーダーレス＋画面全体の取得を試してください。
- 配信側の受信が切れた場合は再接続。キーフレーム間隔は約1秒で、完全にゼロ遅延ではありません。

送信側で重いプレビューやシーン合成をしない設計ですが、OBSより軽いことを保証するものではありません。映像の取得・縮小・圧縮には引き続き負荷がかかります。同じ画質でゲームFPS、CPU/GPU使用率を実測してください。

## スイッチャー

### 使いたい機能だけ表示

左メニューから以下を個別に表示・非表示にできます。

- モニター：PREVIEW / PROGRAM
- シーン：OBSにある全シーンのプレビューカード
- 音声ミキサー：ミュート・音量調整（実際のレベルメーターではありません）
- ソース：次に出すシーンのソース表示切替
- 送信PC：6枠の接続状態・接続コード
- 配信・録画：開始停止、トランジション選択・時間
- 接続設定

見出しをドラッグして並べ替え。タッチ端末では↑↓ボタンを使用。シーンパネルの幅切替にも対応。
配置・表示状態・プレビュー更新間隔は操作端末のブラウザーに保存します。非表示はパネル表示だけに作用し、映像送信やOBSのソースを停止しません。

### 全シーンをプレビュー

受信6枠に限定せず、既存のOBSシーンもすべてプレビューカードとして出します。
一覧と大きなモニターはOBS WebSocketのスクリーンショットを1秒／2秒／5秒間隔で更新します。30/60fpsの動画マルチビューではありません。映像自体の受信・本配信は動画です。
スクリーンショットは2件ずつ取得、1秒キャッシュ。初回は全シーンを取得し、以降は画面に見えるカードを更新。送信PCからプレビュー用に映像をもう1本送ることはありません。

シーンカードをクリック → PREVIEW。TAKEでトランジション、CUTで即本番切替。
数字キー1〜9でシーン選択、EnterでTAKE。入力欄に入力中は反応しません。操作画面にフォーカスがある時だけ有効です。

### OBSソースについて

- 「6枠追加」は `OCS / PC 01` ～ `06` とブラウザーソース `OCS-Receiver-01` ～ `06` を作成します。
- 同じ名前のシーン・ソースがある場合は再利用して二重作成を避けます。既存ソースの設定は上書きしません。
- 非表示時にブラウザーソースをシャットダウンせず、接続を維持する設定です。
- OBSのブラウザーソースは1920×1080、受信映像はアスペクト比を保って表示。
- OBSキャンバスが1920×1080以外の場合は、OBS側でソースを画面に合わせて変形してください。
- 音声はOBSにルーティングされ、通常のOBSミキサーで扱えます。
- 1枠につき受信接続は最大2。通常はOBSの1接続だけを使います。別のブラウザーで受信URLを開くと追加の上り帯域を使います。

## iPad

配信PC内では `http://localhost:17640`、iPadからは公開設定したHTTPS URLで操作画面へアクセスします。
同じLANだけで使う場合は、`OCS_URLS=http://0.0.0.0:17640` を設定してHostを起動する方法もありますが、初期値はローカルPCのみに待ち受けます。外部公開はHTTPSを使用してください。

## 接続できない時

1. 送信アプリが「接続中」のまま：公開URL、DNS、HTTPS、Host起動、ファイアウォールを確認。
2. 「接続済み／受信待ち」のまま：OBSの受信シーンを作成しているか確認。接続コードの枠が一致しているか確認。
3. WebRTCがfailed：別回線のICE接続失敗の可能性。TURN設定を確認。
4. 映像だけ黒い：取得ウィンドウ、ボーダーレス、エンコーダーログを確認。まず720p30で試す。
5. 音声が出ない：再生音／マイク選択、Windowsの既定デバイス、OBSミュートと音声モニタリング設定を確認。
6. OBSに接続できない：4455、WebSocket有効、パスワード、OBS起動を確認。
7. 古い映像が残る：受信ページは停止を検出して再接続を試みます。OBSでブラウザーソースを更新して再試行。

## 更新・ビルド

更新時はHostとSenderを終了し、`host/config.json` をバックアップしてからアプリファイルを入れ替えます。config.jsonを他人へ配布しないでください。操作URLと送信コードを知る人だけが接続できるように扱います。

.NET 8 SDKを使ってソースからビルドできます。

```powershell
dotnet publish Sender/Sender.csproj -c Release -r win-x64 --self-contained true -o dist/OCS-Link/sender
dotnet publish Host/Host.csproj -c Release -r win-x64 --self-contained true -o dist/OCS-Link/host
dotnet run --project Tests/Tests.csproj
```

Hostの初回起動で設定を生成します。配布ZIPには個人用の接続コード・OBSパスワード・config.jsonは含めていません。


## 0.1.1 OBS接続修正

- 認証だけで成功にせず、GetVersionとシーン一覧の応答を検証してから完了表示。
- 接続し直す前の古い状態更新が「未接続」を上書きしないように修正。
- 接続ごとに受信処理・応答待ちを分離し、古い接続の終了が新しい接続へ影響しないように修正。
- 接続設定のOBS URL・パスワードは「OBS接続」を押した時点でも使用。接続確認後に保存。
- 切断コード・理由を画面の赤いメッセージと host/obs-connection.log に記録。
- 更新後の画面ファイルが古いキャッシュに残らないように修正。

設定と接続コードは host/config.json に保存されており、更新ZIPにはconfig.jsonを含めていません。


## distが作られない・完成しない場合

作成先は `BUILD.bat` と同じフォルダーの `dist/OCS-Link/` です。
ビルド開始時に出力先を表示し、SDK確認・テスト・送信アプリ作成・配信側作成・出力確認の順に進行状況を表示します。
`BUILD COMPLETE` が出た時点で完成です。フォルダーだけが存在する場合は、まだビルド中か失敗しています。

途中で止まった場合は、同じフォルダーの `BUILD.log` と `BUILD.status.json` に失敗した段階と理由が残ります。
ビルドが正常終了したときは、完成したフォルダーを自動で開きます。
既存の `host/config.json` は削除しません。


## 0.1.2 プレビュー切替の506修正

OBSの506はスタジオモードOFFを表します。接続時・プレビュー選択時・TAKE時にスタジオモードの状態を確認し、OFFならONの反映を確認してから操作します。
状態確認の直後に外部からOFFへ切り替わった場合も、506に限って一度だけ復旧して再試行します。シーン選択で本番映像を直接切り替える処理は行いません。
3秒以内にONを確認できなければ、OBS右下のスタジオモードをONにする案内を表示します。


## 更新ビルド中に「ファイルが使用中」と出る場合

`OCS-Host.dll` や `OCS-Sender.dll` は、アプリが起動中だと上書きできません。
OCS Hostの黒いウィンドウを閉じ、Senderはトレイの「終了」から終了してから `BUILD.bat` を実行してください。OBS本体の終了は不要です。

ビルド前に、この出力先から起動しているOCS Host/SenderとDLLのロックを確認します。
起動中ならプロセス名とPIDを表示して中断します。アプリを自動終了する処理は入れていません。
送信・配信側の作成直前にも再確認します。`BUILD COMPLETE` が出るまではOCSを起動しないでください。


## 0.1.3 受信接続の診断とビルド時ロック確認

受信ページで起きた映像形式の交渉エラーやICE接続状態を、送信アプリのログにも表示します。
受信側の再接続時に古い接続のエラーが新しい接続を閉じないよう修正し、再試行間隔を2.5秒から最大15秒まで段階的に増やします。
`gdigrab: not enough frames to estimate rate` は入力開始時のフレームレート推定に関する警告です。エンコーダーの終了や接続切断とは分けてログを確認してください。
映像形式の交渉で失敗した場合は `negotiation`、回線の接続に失敗した場合は `ICE` の行を確認します。
別の家同士でICE接続に失敗する場合は、引き続きTURNなどの到達可能な経路が必要です。

更新後はHostとSenderを再起動し、配信側の「送信PC → 受信ページを更新」を押してください。
OBSのブラウザーソース自体も再読み込みし、新しい受信処理へ切り替えます。操作画面のCtrl+F5だけでは、OBS内の受信ページは更新されません。
